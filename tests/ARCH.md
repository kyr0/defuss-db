# Test architecture

Tests use real memory/file/OPFS adapters, not mocked storage. `database.test.ts` checks query semantics, native values, indexes, lifecycle and transaction invariants. It compares indexed results against forced scans and an independent JavaScript oracle, and aggregate outputs against DataView directly over arrays. `native.test.ts` uses temporary directories, separate Node/Bun processes and SIGKILL trials. All processes/directories are task-owned.

`browser-entry.ts` and `browser-examples.ts` are bundled from an installed tarball into real dedicated Workers. `browser-examples.ts` runs seven public examples (price history at earlier revisions, index pages, snapshots and a rejected stale write, three search modes, grouping, a Brotli archive round trip and an OPFS counter) as 18 checks. The e2e driver checks OPFS restart persistence, native values, snapshot isolation, aggregation, indexes and competing workers. `types.ts` checks inferred aliases and compile-time rejection of incorrect fields/IDs. Coverage measures the Node test run; browser checks are reported separately rather than added to coverage artificially.

`search.test.ts` compares all three engines with upstream oracles and exercises typed IDs, pre-top-k filters, language stemming, DDL, rollback, read-your-writes, capacity/cancellation, compaction, reopen and rejection of stores written in another format. A transparent instrumenting proxy counts operations against real DBSONL transactions; it does not substitute fake storage.

`archive.test.ts` checks native graphs, typed IDs, snapshot exports, fragments/reused buffers, merge policies, corruption/truncation, malformed logical records, decompression limits, atomic rollback and cancellation. `cache.test.ts` checks revision/handle/snapshot/transaction isolation, result ownership, key/options/page capture, budgets, admission, eviction, bypasses and clear epochs.

`automatic-cache.test.ts` adds default qualification/manual overrides, plan memory bounds and mutation safety, exact descriptor shapes/property order, independent native constants, instrumented real-store scan sharing, budget/signal isolation, pending errors and clear epochs. Browser tests allow either an overlapping miss or a normal hit because OPFS scheduling may serialize snapshot opening. The real-store instrumented test proves eight overlapping requests perform one scan.

`ordered.test.ts` compares the ordered tuple encoding against DataView, reads against forced scans, and index pages against complete reference traversals. It instruments real DBSONL reads, exercises the 4,096-unit key boundary, tests 128/129-pointer planning, and covers cyclic indexed paths, cursor ownership, stale markers, broken pointers, cache reuse and import replacement. The SIGKILL trials in `native.test.ts` audit equality, ordered and hybrid indexes together. The packed e2e suite imports a history archive written under Node.js into the browser and reads the browser's archive back under Node.js.

`compaction.test.ts` checks the automatic compaction triggers on real memory stores: the bound under sustained writes from one and from two connections, the idle copy, close during a copy, a manual compaction and invalid settings. The bound, idle and manual-compaction assertions were shown to fail with the logic they cover removed.

`parallel.test.ts` runs real query worker threads on directory stores: they are on by default, start on the first eligible aggregate without delaying it and turn off with `parallel: false`; merged aggregates and counts equal one thread, including in snapshots; compensated sums, index-narrowed plans, transactions and small collections stay in one thread; a failing worker's query runs again in one thread with its own error; cancelled queries and invalid settings reject. `batches.test.ts` checks that pool batches yield every key once and in order across the bounded first scan and in DBSONL worker threads, that spans split by measured bytes, and that aggregates and first pages equal those of one thread. `measured.test.ts` checks that a row the source measured is not measured again and that every other row is measured directly.

`index-only.test.ts` checks mixed typed IDs, canonical encodings, pagination, ranges, output/work bounds, cancellation, pinned and staged reads, and malformed pointers. The physical I/O probe in `ordered.test.ts` records primary gets separately from index row visits. The packed suite continues index-page cursors and runs the website playgrounds inside Chromium.

`schema-validation.test.ts` validates the documents of inferred schemas, checks every write path of a collection with a schema (alone, batched and in transactions), the bounded warning of `setSchema`, the conflict of a write that read no schema, `_collections` on the database, a transaction and a snapshot, the entries in an archive, and the corruption cases of `verify()` through raw DBSONL writes. It writes violating documents with `validate: false` through every write method and restores one.

`history-prune.test.ts` prunes by cutoff, by slice and by ID, reads the range before, inside and after, restores a deleted document after a prune, keeps a version that a bounded correction resumes, checks a `temporalUnique` index over a pruned slice, removes deleted documents alone and in one transaction with their delete, prunes 300 documents and one 120-version timeline under a 64-operation transaction limit, restores a full-history archive of a pruned store, and runs `verify()` after every prune.
