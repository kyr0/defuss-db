# Script architecture

`e2e.mjs` creates a clean temporary consumer, installs the tarball, runs Node/Bun ESM/CommonJS and type checks, then bundles that installed package for real Chromium workers. Its loopback server serves only generated test assets. Browser errors fail the check. `process.mjs` is the child-process workload for concurrency and forced termination tests.

`bench.mjs` measures deterministic 20,000-row memory/file workloads with an oracle check, one warmup and nine samples. It records environment and raw timings. `release.mjs` packages authored source, distribution, lockfile and verification evidence with checksums; it never publishes remotely. No script uses production data or credentials. Environment overrides are documented in `.env.example`.

`bench-history.mjs` waits for background compaction to finish, and for query workers to start, before each series and again after its warmups, then measures indexed and forced-scan plans on each backend, index maintenance on inserts, live and temporal operations, ranked searches, and directory reopen. Standalone DataView runs exclusively in the memory fixture. `workload-report.mjs` validates the source data used by the website and release. `make bench-workloads` runs Node and Bun. Each report includes every timed sample and fixture dimensions.

`bench-mongo.mjs` compares directory storage with the MongoDB server at `MONGODB_URL` on the same machine; it waits for defuss-db's background compaction after its load, before MongoDB loads or anything is read: identical documents and compound index, results checked against each other and a JavaScript oracle, MongoDB writes with `w: 1` and `j: true`, a flush probe through defuss-storage, the adapter defuss-db commits with, and a transaction probe. Its one-thread handle opens with `parallel: false`; the full-scan aggregate also runs on a second handle with query workers and exact sums. It creates and drops a throwaway database. `mongo-report.mjs` validates those reports and derives the rows both published pages print.

`e2e-site.mjs` serves the generated `docs/` with `serve-site.mjs` and drives every page in Chromium at desktop and phone width, failing on console errors, failed requests and horizontal overflow, then runs every landing-page control, the comparison charts and the embedded playground's Restart.

`demo-build.mjs` bundles the Ledger playground from `website/demo/` into `docs/demo/`: the page, the database worker with defuss-db from `dist/`, and the defuss-shadcn 0.9.14 runtime and fonts it uses, so the page loads nothing from another origin. `e2e-demo.mjs` drives every playground tab in a fresh Chromium context at desktop and phone width: the first-visit seed, grid sorting, index pages and a status edit, the reports, price corrections read at earlier revisions, transfers that keep the balance total, a rolled-back transfer, search, persistence across a reload and Reset data. `make site` runs `demo-build.mjs`; `make e2e-site` runs `e2e-demo.mjs`.
