# Script architecture

`e2e.mjs` creates a clean temporary consumer, installs the tarball, runs Node/Bun ESM/CommonJS and type checks, then bundles that installed package for real Chromium workers. Its loopback server serves only generated test assets. Browser errors fail the check. `process.mjs` is the child-process workload for concurrency and forced termination tests.

`bench.mjs` measures deterministic 20,000-row memory/file workloads with an oracle check, one warmup and nine samples. It records environment and raw timings. `release.mjs` packages authored source, distribution, lockfile and verification evidence with checksums; it never publishes remotely. No script uses production data or credentials. Environment overrides are documented in `.env.example`.

`bench-history.mjs` waits for background compaction to finish, and for query workers to start, before each series and again after its warmups, then measures indexed and forced-scan plans on each backend, index maintenance on inserts, live and temporal operations, ranked searches, and directory reopen. Standalone DataView runs exclusively in the memory fixture. `workload-report.mjs` validates the source data used by the website and release. `make bench-workloads` runs Node and Bun. Each report includes every timed sample and fixture dimensions.

`bench-mongo.mjs` compares directory storage with the MongoDB server at `MONGODB_URL` on the same machine; it waits for defuss-db's background compaction after its load, before MongoDB loads or anything is read: identical documents and compound index, results checked against each other and a JavaScript oracle, MongoDB writes with `w: 1` and `j: true`, a flush probe through defuss-storage, the adapter defuss-db commits with, and a transaction probe. Its one-thread handle opens with `parallel: false`; the full-scan aggregate also runs on a second handle with query workers and exact sums. It creates and drops a throwaway database. `mongo-report.mjs` validates those reports and derives the rows both published pages print.

`make bench-runs` repeats both benchmarks in eight runs (`RUNS`) and `bench-merge.mjs` writes one report per benchmark and runtime from them: each workload's results come from the run with the lowest geometric mean of that workload's medians. Other processes on the host slow a whole run down, so the median of one run moves with the host. VERIFIED (2026-11-23, 18 cores, one-minute load 3 to 10): between eight runs of one build the median of a series differed by a typical factor of 1.44 under Node.js and 1.60 under Bun. A mean or median over the runs would keep that load in the number; the lowest median per series would break the pairing of the paths and systems that a workload compares, since their samples share rounds only within one run. `site-evidence.mjs` copies the runs to `docs/benchmarks/runs/`, and `workload-report.mjs` and `mongo-report.mjs` fail when a published report is not the merge of the runs beside it.

`e2e-site.mjs` serves the generated `docs/` with `serve-site.mjs` and drives every page in Chromium at desktop and phone width, failing on console errors, failed requests and horizontal overflow, then runs every landing-page control, the comparison charts, the embedded Database Explorer (its three sample databases and the site's theme) and the embedded playground's Restart. Two fresh browser profiles check that the explorer becomes ready after a first visit was left during its seed, and in a second tab opened during the seed. In the API reference app it opens every route, sends the example of every member the page can run on a fresh sample, and checks the duplicate-ID error, a member the page cannot run, the keyword search, a page's Markdown, the theme shared with the landing page and the phone drawer.

`demo-build.mjs` bundles the Ledger playground from `website/demo/` into `docs/demo/`: the page, the database worker with defuss-db from `dist/`, and the defuss-shadcn 0.9.14 runtime and fonts it uses, so the page loads nothing from another origin. `e2e-demo.mjs` drives every playground tab in a fresh Chromium context at desktop and phone width: the first-visit seed, grid sorting, index pages and a status edit, the reports, price corrections read at earlier revisions, transfers that keep the balance total, a rolled-back transfer, search, persistence across a reload and Reset data. `make site` runs `demo-build.mjs`; `make e2e-site` runs `e2e-demo.mjs`.

`shadcn-sync.mjs` copies two apps that defuss-shadcn builds. It reads them from that repository's current commit, not from `dist/` on disk: defuss-shadcn's build rewrites `dist/` in place, and folders vanish while it runs (VERIFIED 2026-11-22), while a commit's files never change.

Into `docs/database-explorer/` it copies the Database Explorer. Files stay byte for byte, except the URLs in `index.html` and `docs-theme.css`. The upstream page names defuss-dom-router, defuss-i18n and lucide on jsDelivr and unpkg; the copy loads them from this repository's devDependencies, and the script fails when their versions differ from the page's, so the page loads nothing from another origin. Into `docs/application/` it copies the API reference app's component bundle, theme and fonts, unchanged. The app's page is adapted by hand in `website/application/`, and the script warns when the upstream page's SHA-256 differs from the one that page names, so an upstream change gets carried over. Every file is read before anything is written, so a missing upstream file leaves both copies as they were.

It runs by hand after defuss-shadcn commits a new build, because this repository cannot build the apps: their pages, component bundles and the explorer's database worker come from defuss-shadcn's own build. Each folder's `SOURCES.json` records every file's origin and SHA-256, and `check-site.mjs` fails when a copied file no longer matches.

`api-docs.mjs` builds the API reference app into `docs/application/`. `make site` runs it after `site.mjs`, which writes the guides its links point to. It renders the sections of `docs/API.md` as the app's guides and reads every member of its method tables, with the signature TypeScript's parser finds in `dist/*.d.mts`, into the page's data block. It fails on a member the declarations lack, a public class method without a row, and an example for a member the reference lacks. It bundles the page's runtime with esbuild, and writes every page once more as Markdown and JSON with `index.md`, `index.json` and `llms.txt`, for readers that run no JavaScript.
